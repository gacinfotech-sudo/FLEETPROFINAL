# Booking — Real-World Gap Analysis

Evidence-based action matrix, classified per the spec's own categories. Built from `docs/BOOKING_CURRENT_STATE_AUDIT.md`, `docs/CUSTOMER_QUICK_ACTION_AUDIT.md`, `docs/TRIP_COSTING_DATA_MAPPING.md`, `docs/TAXI_INVOICE_FIELD_MAPPING.md`, and `docs/GLOBAL_FILTER_SORT_AUDIT.md`.

Classification legend: `FULLY_WORKING`, `PARTIALLY_WORKING`, `UI_ONLY`, `HARDCODED`, `DUPLICATED`, `DISCONNECTED`, `BROKEN`, `DATA_LOSS_RISK`, `FINANCIAL_RISK`, `NOT_TESTED`.

## Priority for implementation (P0/P1 first, per spec's own release-gate emphasis)

**P0 (workflow-breaking or financial-risk, safe to fix now):**
1. Customer 360 → New Booking (core spec ask, zero backend risk — reuses existing prefill mechanism).
2. Unknown number → Quick Inquiry CTA (reuses existing component verbatim).
3. Inquiries/Leads pagination fix (backend already correct; pure frontend wiring).
4. `searchTerm` tab-isolation fix (small, real, prevents confusing cross-tab filtering).

**P1 (real value, moderate scope, still additive/reversible):**
5. Global Customer Search component.
6. Frequent Routes (tenant-DB-derived) + Route Template master.
7. Use Previous Booking as Template.
8. Booking form progressive-sections reorganization (UI-only, no field/logic change).
9. Shared FilterBar rollout, starting with the pages that already have server-side search (Customers/Inquiries/Leads), then Bookings/Drivers/Fleet.

**P2 (real but larger, sequenced last, each is its own safe sub-phase):**
10. Estimated/Actual/Billable KM fields + odometer variance (additive schema, no UI removal).
11. Driver Trip Expense extension (`Expense` model gets optional `bookingId`/`driverId`/chargeable/approval fields).
12. Taxi invoice line items + trip/KM fields on the *real* invoice path (`customer-invoices.tsx`/`invoiceService.ts` only — never the disconnected generator).
13. Server-side pagination for Bookings/Drivers/Fleet.

**Explicitly out of scope for this initiative (documented, not silently dropped):**
- Unifying Add/Edit Booking into one form (high blast radius, separate phase).
- Deep Quotation↔Booking rate-snapshot linkage (separate phase).
- Route distance estimation actually calling a live Maps provider (blocked on credentials — adapter + "Configuration Required" state only).
- CGST/SGST/IGST split (no confirmed tenant requirement — would be inventing tax rules, explicitly forbidden).
- Fixing/removing the dead `invoice-template.tsx` or the disconnected `enhanced-invoice-generator.tsx` (flagged, not touched).
