## Summary

**Total requirements audited: 38** (31 Booking rows incl. 4 named bugs, 13 Financial rows). Breakdown: **19 ✅ VERIFIED_COMPLETE**, **8 🟢 IMPLEMENTED_NEEDS_FINAL_TEST**, **7 🟡 PARTIALLY_IMPLEMENTED**, **2 ❌ NOT_IMPLEMENTED**, **1 🛠 BROKEN_NEEDS_REPAIR**, **1 inconclusive (NO_EVIDENCE)**.

**Most important finding: BUG-MONEY-001 (leading-zero / clear-to-empty in money fields) is not actually fixed anywhere.** Trunk's uncommitted WIP fixes only the Base Amount field (1 of 7 — Toll/Parking/Petrol/Diesel/CNG/Misc are all still on the old broken pattern today). The more complete fix in `money-rootcause` (all 7 fields + shared utility) self-reports **0 of 5 live Playwright E2E tests passing** — clearing Base Amount still snaps back to "0", plausibly tied to `amount: z.number().min(1)` lacking `.optional()`. Neither trunk nor any worktree has a verified-working fix.

**Second finding (good news):** most of the flexible-booking rules the user cares about (vehicle-optional/Allocation Pending, Date Not Decided as a real sentinel not a fake date, Own/Vendor/Outsource, override-with-reason Trip Start gating) are genuinely and fully wired end-to-end on trunk — not just present in an isolated worktree. This contradicts an earlier, now-stale internal audit that found vehicleId still hard-required.

**Third:** the short `bookingCode` feature is fully built and unit-tested but completely unreachable — zero references anywhere in trunk's server or client code.

**Fourth:** the Live Preview (:5051) is missing the entire booking-queues feature (real 401 JSON on trunk vs. SPA-fallback 200 HTML on Preview for the identical path) — Live/Upcoming-adjacent findability queues, follow-up-due tracking, and previous-booking reuse are all absent from what the user is actually browsing, even though trunk has them.

**Fifth:** Invoice snapshot immutability is implemented correctly and deliberately — frozen amounts and live-recomputed "current" settlement figures are kept as distinct, separately-named fields.
