# Security / Tenant-Isolation / RBAC / Test-Infrastructure — Evidence Audit

Read-only audit. No servers started, no migrations run, no git state changed, no
data written to the shared MongoDB. Date: 2026-08-07.

Scope: trunk (`fleetpro-main`, branch `booking/integration-preview` @ `20bd273`,
dirty), Live Preview (`fleetpro-stable-demo`, `runtime/stable-demo` @ `bdf4457`,
reachable at 127.0.0.1:5051), and worktrees covering driver/gps/telephony
security work plus cross-cutting QA.

## Headline finding

**No confirmed tenant-isolation leak (P0) was found in any code path that is
actually integrated into trunk or Live Preview.** Every single-record read/update/
delete reachable from `booking/integration-preview`'s `server/routes.ts` (231 route
registrations, 91 direct Mongoose `findOne`/`findById` calls checked) includes a
`tenantId` filter sourced from the authenticated session (`req.tenantId`), never
from the client-supplied body/params, enforced via the `scopeTenant(req)` helper
(`server/routes.ts:152`) or an equivalent `tenantContext(req,res)` guard inside
`server/gps/routes/*.ts`. This is `VERIFIED_CODE`, not `VERIFIED_RUNTIME` — no
cross-tenant credentials were available to exercise it live, per the task's
safety constraints. `curl` checks against both Live Preview (5051) and trunk dev
(5050) confirm unauthenticated requests to `/api/vehicles` and `/api/bookings`
correctly return `401`.

The two real, substantiated gaps are: (1) the **RBAC role model does not match the
6-named-role requirement** — this is a genuine, unresolved gap, not paperwork; and
(2) **test infrastructure runs against a shared MongoDB database in nearly every
worktree**, which is a real data-integrity/isolation risk to the live Preview and
concurrent workers, confirmed as BUG-TEST-DB-001. Additionally, a large share of
the security work reviewed here (telephony RBAC, GPS webhook/billing/live-tracking,
driver Google-Drive documents) **exists only in feature worktrees and has not been
merged into the trunk HEAD** (`booking/integration-preview` @ `20bd273`) that this
audit was told is the integrator branch — it lives on a separate, diverged
integration lineage (`integration/preview-20260807` and descendants such as
`integration/reconcile-trunk-booking-20260807`), which trunk's current HEAD is
neither an ancestor nor descendant of.

## Prose summary of most important findings (P0 first)

1. **No P0 tenant-isolation leak confirmed.** Every reachable, trunk-integrated single-record query in `server/routes.ts` and `server/gps/routes/**` filters by a server-derived `tenantId` before the query executes (`scopeTenant(req)` / `tenantContext(req,res)`), not after. This was checked across 91 direct Mongoose `findOne` calls plus the `storage-mongodb.ts` `get*(id, tenantId?)` helpers — no bypass path was found. This is `VERIFIED_CODE`, and should be upgraded to `VERIFIED_RUNTIME` only via an actual two-tenant penetration test, which this audit could not perform.

2. **BUG-TEST-DB-001 is real and already active**, not theoretical: 15 of 16 worktrees checked, including the actively-running Live Preview (`fleetpro-stable-demo`) and multiple concurrent security-test suites (`gps-quality-security`'s tenant-isolation/webhook/credential tests), point at the exact same `mongodb://127.0.0.1:27017/fleetpro` database. Only `driver-quality-security` uses a genuinely isolated DB name. This creates real risk of test-data pollution into the Live Preview and cross-worker flakiness; it does not by itself imply a security leak (test data still carries valid tenantIds) but is a serious test-infrastructure gap that should block trusting any of the affected suites' pass/fail results as clean signal.

3. **The RBAC role model does not match the stated 6-role requirement (Owner/Manager/Executive/Finance/HR/Vendor), and this has not changed since the prior audit.** `User.role` remains a hard 3-value enum (`admin`/`client`/`manager`). Finance/HR/Executive-style distinctions are implemented only as permission-string subsets on `manager`-role users, and Vendor is a separate business entity with no login-role identity at all. This is a plain, unresolved gap — call it out rather than treat the permission-array workaround as equivalent.

4. **A significant share of the security-relevant feature work reviewed (telephony multi-user RBAC/tenant isolation, GPS webhook/billing/live-tracking, driver Google-Drive documents) is not merged into the trunk HEAD this audit was pointed at** (`booking/integration-preview` @ `20bd273`). It exists on a diverged integration lineage (`integration/preview-20260807` → `integration/reconcile-trunk-booking-20260807` @ `200919b`) that trunk's current branch is neither an ancestor nor descendant of. Passing tests in those worktrees describe code that is not reachable from what's actually deployable from current trunk today.

5. **The `server/routes.ts` protected-file rule was respected by the 4 driver-domain worktrees audited for BUG-ROUTES-001** (0 self-authored diff lines each), but 3 other worktrees (`feat/booking-code-02`, `test/money-qa-03`, `fix/money-rootcause-01`) each carry ~95 lines of self-authored `routes.ts` changes relative to their own merge-base — a genuine rule violation the Integrator should review before merging those branches.
