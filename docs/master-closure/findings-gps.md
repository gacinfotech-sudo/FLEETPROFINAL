## Important structural finding: trunk/Preview already have a *separate, earlier* GPS foundation

`fleetpro-main` and the Preview worktree both already contain (via trunk commits `ae60cc9`, `64299f1`, `0863fbc`, `1accadd`, predating the `1da105b` branch point all GPS worker worktrees fork from) a **provider-neutral GPS foundation**: `server/gps/models/{gpsConnection,gpsDevice,vehicleGpsAssignment}.ts`, `server/gps/providers/{adapter,registry,runtimeRegistry}.ts`, `server/gps/routes/{connections,devices,assignments}.ts`, `server/gps/services/*`, AES-256-GCM credential encryption (`server/gps/security/credentialEncryption.ts`). These routes ARE mounted in `server/routes.ts` on both trunk and Preview, and ARE live (confirmed: `curl http://127.0.0.1:5050/api/gps/connections` and `:5051/api/gps/connections` both return `401 {"message":"Authentication required"}` — i.e., the route exists and is auth-gated, not a 404).

However, `server/gps/providers/runtimeRegistry.ts` on trunk/Preview is **deliberately empty**:
```
// Real provider factories are registered here only after their official API
// documentation has been supplied and mapped. An empty registry deliberately
// produces Configuration Required instead of a fake successful connection.
export const gpsProviderRegistry = new DefaultGpsProviderRegistry(resolveGpsProviderConnection);
```
So on trunk/Preview today, "Test Connection" always returns `configuration_required` — there is no working provider behind it. The one real adapter that exists (Traccar, in `gps-provider-connections`/`gps-quality-security`) is not registered there. There is also **no GPS client UI at all on trunk/Preview** (`find client -iname "*gps*"` returns 0 files on trunk; `curl :5051/gps-settings` returns the generic SPA shell with no GPS route, confirmed by title tag only).
