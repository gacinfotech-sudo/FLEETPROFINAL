# Pipeline Bug Report — Complete SaaS Pipeline Audit

Findings from 5 parallel evidence-based research passes (file:line cited) plus direct verification, covering pipelines A-D (Inquiry→Lead→Quotation→Customer), I-L (Driver Duty→Trip lifecycle), O/Q/P (Payment/Vendor/Feedback-Rewards), R/S (WhatsApp/Calling), routes/permissions/tenant-isolation, and DB relationships/status-transitions/idempotency. Booking/Customer/Invoice/Costing/Filters pipelines were already deeply audited in the prior "Professional Booking" initiative this session — see `docs/BOOKING_REAL_WORLD_GAP_ANALYSIS.md` for those findings; not repeated here.

Classification legend and severity per the spec's own scheme (`SECURITY_RISK`, `FINANCIAL_RISK`, `DATA_LOSS_RISK`, `PARTIALLY_WORKING`, `DISCONNECTED`, etc.; P0=critical, P1=core pipeline broken, P2=incomplete workflow, P3=usability).

## No action needed (verified correct)

- Payment reversal (`reversePayment`), reward-point transactions, and Google-review-request idempotency (exact-retry case) all use the correct, DB-level-enforced idempotency pattern already.
- All four centralized status-transition validators (Booking/Lead/Inquiry/Quotation) are real, consistently enforced, and none has a raw unvalidated `.status = req.body.status` bypass.
- No wholesale `record = req.body` overwrite pattern exists anywhere in the 5 audited update routes (Vehicle/Driver/Booking/Customer/Invoice) — all go through either a Zod partial schema (which strips unknown keys) or an explicit field allowlist.
- Invoice snapshotting is correct: `customerSnapshot`/`billingSnapshot`/`businessSnapshot`/`bookingSnapshot` are plain-data copies at generation time, never live-populated, so editing a Customer later cannot silently rewrite a finalized invoice.
- Tenant isolation spot-check (5 different models) found `tenantId` is consistently server-derived from the authenticated session (`req.tenantId`), never client-supplied, in every query checked.
- `findOrCreateCustomer` is genuinely shared/reused (not duplicated) by both the Inquiry/Lead/Quotation→Customer pipeline and the direct booking-creation path.
