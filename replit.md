# FleetPro - Fleet Management System

## Overview

FleetPro is a comprehensive multi-tenant fleet management system designed for taxi and car rental businesses. The application enables business owners to manage their vehicles, drivers, bookings, and revenue through a modern web interface, with separate admin and client portals.

## System Architecture

The application follows a full-stack architecture with the following key components:

### Frontend Architecture
- **Framework**: React 18 with TypeScript
- **Routing**: Wouter for client-side routing
- **State Management**: TanStack Query for server state management
- **UI Components**: Radix UI with shadcn/ui component library
- **Styling**: Tailwind CSS with CSS variables for theming
- **Build Tool**: Vite for development and production builds

### Backend Architecture
- **Runtime**: Node.js with Express.js framework
- **Database**: PostgreSQL with Drizzle ORM
- **Authentication**: Session-based authentication with express-session
- **Middleware**: Custom authentication middleware for role-based access control
- **API Design**: RESTful API endpoints with proper error handling

### Multi-Tenant Architecture
The system implements tenant isolation where:
- Admin users can manage multiple tenants (clients)
- Client users are restricted to their own tenant data
- Database schema includes tenant-specific filtering for data security

## Key Components

### Database Schema
- **Tenants**: Business information and configuration
- **Users**: Authentication and role management (admin/client)
- **Vehicles**: Fleet inventory with specifications and rates
- **Drivers**: Driver profiles with licensing and availability
- **Bookings**: Trip reservations and scheduling

### Authentication System
- Role-based access control (admin vs client)
- Single session enforcement to prevent concurrent logins
- Session-based authentication with secure cookie management
- Middleware for route protection and tenant isolation

### User Interface Components
- **Admin Panel**: Tenant management, user creation, system overview
- **Client Dashboard**: Booking management, fleet viewing, revenue tracking
- **Responsive Design**: Mobile-first approach with sidebar navigation
- **Form Validation**: React Hook Form with Zod schema validation

### API Structure
- `/api/auth/*` - Authentication endpoints
- `/api/admin/*` - Admin-only operations
- `/api/vehicles` - Vehicle management
- `/api/drivers` - Driver management
- `/api/bookings` - Booking operations

## Data Flow

1. **Authentication Flow**: Users log in with userId/password, receive session cookie
2. **Authorization**: Middleware validates sessions and enforces tenant isolation
3. **Client Operations**: Tenant-scoped CRUD operations for business entities
4. **Admin Operations**: Cross-tenant management and system administration

## External Dependencies

### Frontend Dependencies
- React ecosystem (React, React DOM, React Hook Form)
- UI libraries (Radix UI, Lucide React icons)
- Utility libraries (date-fns, clsx, class-variance-authority)
- Development tools (Vite, TypeScript, Tailwind CSS)

### Backend Dependencies
- Database (Drizzle ORM, @neondatabase/serverless, PostgreSQL)
- Authentication (bcrypt, express-session, connect-pg-simple)
- Utilities (nanoid for ID generation, zod for validation)

## Deployment Strategy

### Development
- **Environment**: Replit with Node.js 20 runtime
- **Database**: PostgreSQL 16 module
- **Hot Reload**: Vite dev server with HMR
- **Port Configuration**: Application runs on port 5000

### Production Build
- **Frontend**: Vite builds static assets to `dist/public`
- **Backend**: esbuild bundles server code to `dist/index.js`
- **Deployment**: Replit autoscale deployment target
- **Environment Variables**: DATABASE_URL and SESSION_SECRET required

### Database Management
- **Migrations**: Drizzle migrations in `./migrations` directory
- **Schema**: Centralized in `shared/schema.ts`
- **Connection**: Neon serverless PostgreSQL with connection pooling
